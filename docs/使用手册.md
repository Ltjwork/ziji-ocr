# 字迹（ZiJi）

书籍电子化校对工具（原名「古籍拆字工具」，1.0.0+103 起更名）：古籍图片自动切字 + 人工校正 + 可追溯数据集导出与模型训练。

当前版本将识别结果视为初稿：正文区域、自然段、行和单字都必须经过人工确认后，才会进入正式训练数据集。每次识别会保留原图哈希、OCR 修订号、模型版本、阅读方向和稳定 UID，重新识别不会覆盖旧标注。

## 目录结构

```
ocr/
├── flutter_app/       # 桌面端 UI
└── python_service/    # 图像处理服务（OpenCV + FastAPI）
```

## 首次安装

1. 进入 `python_service/` 目录，双击运行 `install.bat`
2. 或手动执行：

```bash
cd python_service
pip install -r requirements.txt
```

（可选）启用 PaddleOCR 识别引擎：另运行 `install_paddleocr.bat` 建独立 `paddleocr` 环境（GPU 默认装 cu126 轮子，`PADDLE_PADDLE=cpu` 装 CPU 版）；或在应用内「环境准备」页点「安装 PaddleOCR 引擎」。

## 识别引擎（Kraken / PaddleOCR，每本书可选）

识别引擎只负责"读字"：版面/行/字框由自训 YOLO 模型 + 像素切分器给出（**engine=paddle 时行框升级为 PP-OCR det 文本检测**，见下），两路读法对齐融合（正文优先对齐序列字、序列漏读取框内读法、分歧位挂候选）也完全复用同一套管线。**全文对照**（默认识别流程附加路，默认开）：以**文本视图整页直读的行文本**（随直读落盘的行记录；VL 选择时带标点）为参照，与单字识别序列逐行对齐——整页有而单行字框没有的字符（通常是标点）以**紫色无框字片**显示在识别栏字片序列尾部，与对位整页文本不一致的单字以**深橙**标记（墨迹校验红/琥珀优先级更高）。标记在识别时随识别写入；**整页直读完成后会自动按最新行记录刷新标注里的标记**（纯 CPU 毫秒级，提示"整页对照已按最新直读刷新"）——所以推荐顺序：先在文本视图直读一次，再看标注视图的单行对照。行记录缺位/行未命中时该行自动回退行框裁图逐行直读作参照；`FULL_TEXT_CHECK=0` 可整体关闭。**PaddleOCR-VL 仅支持整页直读（文本视图）**：本书选 VL 时行/单字识别自动回退 PP-OCRv6_small_rec（客户端选择不变），不报错。

- **PP-OCR det 定行（engine=paddle 专属，1.0.0+205 起）**：Paddle 引擎时 `/segment` 与 `/segment_lines_in_region` 的**行框改用 PP-OCR det 文本检测**（与 PaddleOCR 官网演示同一检测模型，检测档位自动跟随识别档位）——自训 YOLO 字框分组在部分影印本上行框碎片/粘连/漏检严重（整列漏检、句号成独立行框、夹注并进正文），det 对同类页面行框准确（实测 6034×8534 竖排页 17 列全检出、约 0.7s/页）。行内**字框仍由像素切分器**逐行给出（识别/融合/全文对照链路不变）；det 失败或无产出自动回退 YOLO 行框（识别不中断）；kraken 引擎书的行框链路完全不变。识别信息脚注显示"**PP-OCR 检测定行**"（蓝色）。`OCR_PADDLE_DET_LINES=0` 可整体停用回退旧行为。**升级后需重新执行"识别当前页"**，存量标注里的旧 YOLO 行框不会被自动替换。
- **det 行版面类型（1.0.0+206 起）**：det 检出的**页眉/页脚/页码**内容自动打类型标签——优先按人工已确认门控区归属，无区时按几何位置判定（页顶/页底边带内的短行，25% 版高上限保证正文主列永不误标；页脚带内 ≤5 字的极短行判页码）。类型行在行视图用**与区域视图同款的类型配色**画框并标注类型名（页眉青/页脚蓝灰/页码绿/眉批黄棕），导出/后续处理按批注类对待；单行重识别保留类型不丢。页面中部短行（正文/眉批候选）不猜类型，避免误标。

- **选择位置**：新建任务页「识别引擎」卡片（Paddle 档位预填全局默认）；进入书籍后编辑器「页面操作 → 识别引擎（本书）」随时切换（书级设置，落盘 `project.json` 的 `settings.engine` / `settings.paddle_model`，下次识别生效，已确认标注不受影响）。
- **模型管理与默认档（设置页）**：「AI 辅助设置 → PaddleOCR 模型」卡逐档展示说明（体积 + 电脑配置要求）与已下载状态、可逐个预下载（`/paddle/download`：一次性临时进程下载/自检，不影响正在使用的池），点选即设**默认档**（存全局设置 `paddle_model`，新建任务预填；每本书仍可在编辑器里单独覆盖）。已下载检测走官方缓存目录（`~/.paddlex/official_models/`，`PADDLE_PDX_CACHE_HOME` 可覆写）。
- **Kraken（默认）**：CHAT 古籍识别模型，`kraken` 环境常驻 daemon 池（行为与历史版本一致，不传引擎字段即 Kraken）。
- **PaddleOCR（可选）**：`paddleocr` 独立环境（`paddlepaddle(-gpu)` + `paddleocr>=3.7` + `paddlex[ocr]`），同样常驻 daemon 池但**懒启动**（首次选它识别或探测时才建池，不用不占显存；池按模型绑定，换模型自动重建）。识别模型五档（按电脑配置选）：`PP-OCRv6_tiny_rec`（4.4MB，CPU 即可，精度最低）/ `PP-OCRv6_small_rec`（**20.4MB 蒸馏小模型，默认**，CPU 可跑、入门独显流畅）/ `PP-OCRv6_medium_rec`（73.3MB，建议 ≥4GB 显存 NVIDIA 独显，精度最高）/ `PP-OCRv3_mobile_rec`（9.8MB，老一代轻量档，横排或引擎对照用）/ **`PaddleOCR-VL-1.6`（视觉语言模型 0.9B，下载约 1.9GB，需 ≥8GB 显存独显）——古籍最强**：竖排、小号标点、复杂版式显著强于 PP-OCR 系（实测同一页标点 86 个 vs PP-OCRv6 的 3 个），但**仅整页直读（文本视图）可用**，行/单字识别会自动回退 PP-OCRv6_small_rec；直读为混合方案（VL 读带标点文本 + PP-OCR det 定行框，逐行对齐；**版面分析开启时 VL 块是整段段落，合并器会按阅读序把段落切回逐行、标点落回各行**——1.0.0+207 前开启版面分析会退化为整段落进页尾），速度约 15-20s/页（GPU）。**VL 解析配置**：书内引擎对话框选 VL 模型时展开配置面板（官网演示同款全参数，书级设置）——**模型参数**（图片方向矫正/图片扭曲矫正/版面分析/图表识别/印章识别/图片文字识别，改动=进程池重建）、**Prompt 类型**（文本/公式/表格/图表/印章/文本检测与识别 spotting，仅关闭版面分析时生效；spotting 在超大整页上可能触发底层崩溃，默认文本即可——逐行能力由混合直读的 PP-OCR 几何承担）、**生成参数**（重复抑制强度/识别稳定性/结果可信范围/图像最小/最大总像素数，留空=默认；本地推理暂忽略前三个采样参数）、**辅助内容解析**（页眉/页眉图片/页脚/页脚图片/页码/脚注/旁注文本，默认过滤、开启恢复解析）。Prompt/生成/辅助参数随每次直读请求即时生效（不重建池）。古籍竖排推荐保持默认。首次使用自动从官方源下载（引擎卡片「下载/测试所选模型」按钮即 `/paddle/probe`，会顺带把池预热到该模型）。**注意**：首次用某档要下载模型（small 实测 ~60s、VL-1.6 约 1.9GB 视网速更久；已缓存后加载 small ~5s、VL ~30s），且每次切换模型 = 进程池重建重载——建议先在设置页「PaddleOCR 模型」卡把要用的档预下载好再识别。
- **竖排读法**：PP-OCR 识别模型只有横排域（竖排行直接旋转会把直立字形放倒出乱码），竖排整行序列读法用"字框裁剪 → 等高拼横条"实现（拼条内字形全部直立），与逐字读法构成互相独立的第二路；横排行 Paddle 可直读整行（比 Kraken 的纯逐字读法多一路整行语境）。预处理不做 nlbin 二值化（PP-OCR 期望原始灰度/彩色）。
- **API**（只追加字段不改名）：`/segment`、`/segment_region`、`/segment_lines_in_region`、`/recognize_char` 请求追加 `engine`（默认 `kraken`）与 `paddle_model`；响应 `recognition_engine`（`kraken`/`paddle`）与 `ocr`（如 `paddle+PP-OCRv6_small_rec`）如实回显实际引擎。管理端点：`/paddle/models`（清单+配置要求文案）、`/paddle/status`（含 `downloaded` 已下载清单）、`/paddle/download`（逐档免打扰下载）、`/paddle/probe`（探测+预热）、`/paddle/pool/resize`（`OCR_PADDLE_WORKERS` 覆写，默认 1，钳 1..4）。

## 整页直读（编辑器「文本」视图）

编辑器右侧视图切换（主区/段/行/详细/**文本**）里的「文本」模式：**左右分栏**——左侧书页栏 + 右侧文本栏，画面中心对半。**不走主区/段落/单行/单字的标注管线**，由引擎自己分行读字直接输出整页文本——适合快速通读与 AI 校对，不产生标注框、不进训练数据，与标注校对互不影响。

- **左侧书页栏**：与标注视图同款的书页展示（解码位图、滚轮/手势缩放平移、初始整页适配），**不画任何识别框**。工具条上的「**行文对照**」开关（默认开）：把每行识别出的文本以**小字**（约半列宽）叠加在书页对应行的旁边——竖排行逐字贴列框左缘、只占列间空隙不遮正文与邻列，**逐字与书页文字对齐**（Kraken 直读行带逐字框时按字框对齐，Paddle 无字框时按列高均分对齐）；横排行小字整行画在行框下方。对照小字用**高亮色**（按行序轮换的彩虹色板，同一行同色、相邻行异色，与编辑器单字框同一套颜色语义），白底圆角片 + 同色描边，黑白书页上一眼可辨。在文本栏里编辑某行文字时叠加层按行号实时同步。识别前或行数对不上时叠加层自然缺省/保持识别原文。
- **右侧文本栏**：「识别本页 / 重新识别」（本书当前引擎；首次使用会先下载整页检测模型）→ 可编辑整页文本框 →「AI 校对」→「保存/复制」。状态栏如实区分"文本由 X 识别"（实际产出这份文本的引擎/模型，落盘 `direct_text/<pageId>.meta.json` 侧车记录）与"本书已选 Y"——在书内改了引擎/模型后旧文本不会自动重读，两者不一致时状态栏**橙字提醒**点「重新识别」用新模型重读。
- **识别引擎**：PaddleOCR 走 det+rec 完整管线（PP-OCRv5 起原生支持竖排，页面不旋转；首次自动下载同档检测模型，tiny 1.9MB / small 9.6MB / medium 59.4MB）；Kraken 走 blla 分行（`chat_seg.mlmodel` 首次直读懒加载；竖排小图上 blla 会把列拆成单字级碎片，后端按列中心聚簇合并成整列再交 CHAT 逐行识别）。后端按本书方向设置（列序/行内序）重排成阅读序（`page_text.py`：竖排列聚类 + 列内排序，容忍列中心抖动；btt/rtl 行内反向）。**VL 直读耗时与显存**：VL 0.9B 模型首次推理含权重编译、且与 kraken 池共享显存（每个 kraken daemon 占一份 CUDA 上下文）——显存被挤时首读可达数分钟（单请求超时已放宽到 15 分钟，`PADDLE_VL_READ_TIMEOUT` 可调），超时后重试一次通常即恢复（模型已热约 15-25s/页）；显存持续紧张时可调小 `OCR_KRAKEN_WORKERS`。
- **标点局限（Paddle 直读，PP-OCR 系）**：PP-OCRv6 识别模型按现代排版训练（标点与正文字同高），而古籍影印本的句读/圈点多是**印在字旁的小号符号**（约 0.4 字高、夹在字间空隙里）——整行识别时会被系统性跳过，因此 PP-OCR 系直读的古籍文本**几乎不含标点**（实测：检测框其实包住了这些小符号，属识别模型能力盲区，加大检测框外扩、放大图片等参数均无效）。应对：**选 `PaddleOCR-VL-1.6` 模型直读**（原生读出古籍标点，见识别引擎节）；或直读后用「AI 校对」**断句补全标点**（校对提示词已内置"标点整页缺失时按文意补全"指令，见下条）；需要忠实还原印刷标点时走标注管线（单字识别会把每个小符号单独成框读出）。**诊断日志**：每次 Paddle 直读在后端日志输出标点统计（`mark stats: N lines, text puncts=X, mark-like blobs≈Y, read ratio Z%`——"图上检出的小墨块数 Y"即疑似被跳过的标点规模，逐行还有明细），丢标点的规模可直接量化（VL 模型直读时同一统计可直接对比出标点召回差异）。
- **AI 校对**：按钮触发（不自动跑），优先用视觉模型带整页原图按原行结构校对误识与断句（异体字/繁体保持原样、无把握不改、行数不变），结果预览后自行决定是否采用；未配视觉模型时用文本模型纯上下文校对。**标点补全**：OCR 文本整行/整页几乎没有标点时（古籍小号标点被引擎跳过的典型情形），校对会按文意用标准中文标点断句补全，已有标点保持原样。走「AI 辅助设置」的推理来源与限流。
- **落盘**：`<书目录>/direct_text/<pageId>.txt`（原子写，与页标注 JSON 完全解耦：重识别/标注保存互不影响，也不进训练数据/导出）；识别结果即时落盘、编辑手动保存；翻页自动换内容。
- **API**：`POST /read_page_text`（`image_path/orientation/horizontal_dir/vertical_dir/engine/paddle_model` → `{text, lines, engine, ocr, elapsed_s}`，识别闸门 `_gated_recognition` 保护）。

## 使用流程

1. 点击右上角 `+`，导入古籍图片（支持多选，也支持 PDF——默认"只识别正文/从右到左/不自动跨页拆分"，可改）
2. 输入项目名，进入编辑器
3. 系统自动切块，蓝色框为候选字块
4. 操作：
   - 点击选中框 → 右侧面板调整类型 / 确认 / 删除
   - `Delete` 键删除选中框
   - 在空白区域拖拽绘制新框
   - 选中框后拖拽四角橙色点调整大小；角点外侧也可点击，点击范围随缩放保持可操作大小
   - 滚轮缩放，拖动画布平移

**PDF 导入是三段式、可断点续跑**：复制源文件 → 先落盘书记录（书立即出现在书库，标记"导入未完成"）→ 后台逐页转图（导入按钮实时显示"第 N/M 页"）。转图中途退出应用书也不丢：书卡片点「继续导入」从断点续跑（后端跳过已转换的页，半截文件不算完成），完成后按创建时的选择自动/手动进入识别；未完成的书不能进编辑器、不会被误入识别队列。
5. 两种保存方式（缩略图边框三态：蓝=当前页、绿=已确认、橘黄=临时保存过、灰=从未人工保存）：
   - 「临时保存」（软盘图标）：把当前修改写盘防丢失——只是翻看了一下、或改了一部分还没校完时用它。不确认任何识别框和文字，不计入训练数据，也不计入首页校对进度。直接翻页或退出编辑器时也会自动做一次临时保存，临时保存过的页缩略图显示橘黄框。
   - 「确认并保存」（圆圈对勾图标）：确认本页全部识别框与识别文字，固化为训练标注（缩略图转绿框、计入首页校对进度）。只有这种保存的页面会进入训练数据集。
   - 「确认识别框」（玫红框状态）与主区快设的「确认并下一页」同样计入**检测层**训练数据（正文区/段落/行/字框几何）。**确认即入账**：任何确认类保存（确认并保存/确认识别框/主区快设确认）都会在约 10 秒内自动触发一次后台增量导出（TrainExportScheduler，防抖合并连续确认），训练数据统计随之增长，不必再打开训练页等自动导出；导出完成时编辑器右侧的训练数据卡自动刷新。
   - 校对进度与隐藏已确认页：编辑器底部翻页栏**右侧**常显「未确认 N 页 · 已确认 X/Y（P%）」（与首页卡片同口径，确认/重识别后实时刷新）；左侧缩略图列表头部的「隐藏已确认」开关把绿框页从列表隐去、只列待校对的页（当前页恒显示，翻页仍按真实页序逐页走）。
6. 点击右上角导出图标，选择输出目录，导出字块图片和 `blocks.json`

## 文字汇总（字频统计）

首页顶栏「文字汇总」进入：统计**所有「确认并保存」过的页面**里每个字出现过的次数（正文与批注都计入，忽略块与空文字除外），可按字或拼音筛选，按次数 / 拼音 / Unicode 排序，汇总卡显示收录书籍数（含已删除书）、已确认页数、字种数与总字次。字频展示有两种视图，顶栏按钮随时切换：**网格**（默认，一格一字、格内显示次数，悬停看拼音）与**列表**（大字格 + 拼音 + 占比条 + 次数）。

- 数据存放在书籍数据根目录下的独立账本 `char_stats/`（不在任何书籍目录里），随确认保存自动记账、打开页面时聚合——账本即唯一真相，无冗余总计可失步。
- **删除整本书不影响统计**（校对成果按历史累计保留）；**删除单页 / 页面重新识别 / 全书重新识别**会把对应页面的文字从统计中移出（重新校对确认后再计入）。跨页拆分与「恢复拆分前」自动对账，同一批字不会重复计数。
- 统计口径与墨迹模板（仅正文）不同：这里正文与批注小字都计入，反映书中实际出现的全部文字。
- 升级后首次启动自动把现有书籍的已确认页一次性计入（`char_stats/.backfilled` 标记防重跑）。
- **每本书的正确识别率**（书库卡片显示）：识别结果解析时给每个字记录原始 OCR 文字基线（`orig_text`，人工/AI 改写不碰它、单字重识别会重置），「确认并保存」时按页把"已确认识别字数（total）与其中识别后被修改过的字数（fixed）"记进同一账本（`accuracy` 字段），按书聚合得 正确率 = (total − fixed) / total。人工新画字框与升级前已确认的旧页没有基线、不计入分母（旧书重新识别后再确认才开始累计）。

## AI 画框测试（实验）

首页顶栏「AI 画框测试」进入：选任意图片 → 后端生成带网格刻度的降采样素材图（`/page_prelabel_image`，`grid_div` 默认 8、本页可选 16）→ 视觉模型**直接输出每个字的坐标框** → 原样叠加到原图（0.15×–12× 缩放平移、点选看原图像素坐标、框上编号即 AI 给出的阅读顺序）。与生产链路刻意相反：**零几何精修、不写任何标注、不进训练数据**——专门测「单纯让 AI 决定从哪个像素到哪个像素是一个字」的裸水平。

- **坐标口径两档**：素材图像素（x1/y1/x2/y2，测裸像素定位）/ 归一化 0~1（x/y/w/h，参考网格刻度），同一张图两种口径各跑一次即可对照差距。
- **管线对比 + 计时**：「YOLO+AI 管线」按钮对同一张图跑当前生产管线（YOLO 切字 + Kraken 识别 + 可选 AI 整行裁决，「含 AI 裁决」开关默认按生产门控），面板顶部对比卡并排显示两方案**识别一页各自所用时间**（含分段：纯 AI=素材图+模型，管线=识别+AI 裁决）与产出（框数 vs 行数/字数，含数量差）；画布双色叠加（绿=AI 框带序号、蓝=管线字框、紫=管线行框，顶栏分别显隐）。管线编排与朝代基准共用 `single_page_pipeline.dart`（含识别忙等待重试）。
- **截断是常态**：整页几百个字的 JSON 输出量很大（num_predict 8192、超时 10 分钟仍可能不够），解析器会从截断的 JSON 里逐个打捞已闭合的框、丢弃残尾并标 truncated，页面橙色横幅提示「已打捞 N 框」——截断本身即实验数据（该模型/口径下整页不可行）。
- 走 AI 辅助设置里配置的视觉模型（本地 Ollama / 外部 API 双通道同款），AI 调用自动继承限流与降级重试；素材图依赖后端（应用自动拉起）。

## 识别监控悬浮窗

应用内全局悬浮窗（挂在路由栈之上，任何页面、对话框、编辑器里都可见），用于整本识别挂机时掌握全局。**常驻显示**：首次默认显示，位置、可见状态、折叠态都会被记住。

- **显示内容**：当前任务的进度（书名 + 任务类型「整本识别/按主区拆分」、第 X/共 Y 页、百分比、预计剩余时间）、**任务列表**（运行中任务可「停止」、排队中任务可「删除」）、「全部识别完成后关机」开关（倒计时期间任何页面都能看到剩余秒数并一键取消——此前倒计时横幅只在首页可见），以及整机 CPU / 内存 / 显存 / GPU 利用率的当前值与约 3 分钟滚动曲线（任务管理器口径，每 2 秒刷新）。
- **「按主区拆分」后台任务**（主区快设启动）：与整本识别共用同一队列与监控——启动后留在主区快设可继续观察（任务页锁定并标「队列中/已处理」，完成的页实时刷新），也可自由离开（书库拦编辑入口防互相覆盖）；断点文件（region_split_progress.json）随任务实时维护——启动写全集、每完成一页收窄、全部完成清除，停止/失败/运行中退出应用后，主区快设或首页卡片「继续拆分」都从「尚未完成的页」续跑。
- **操作**：标题栏拖动移动位置；「—」折叠成圆形进度徽标（显示当前书百分比，点击展开）；「×」关闭，首页工具栏的心形图标（monitor_heart）可重新打开。
- **口径说明**：悬浮窗的"系统占用"是**整机**口径，来自后端 `/process_stats` 的 `system` 块（psutil + nvidia-smi；跨语言字段基准声明在 `api_base.py` 的 `_system_stats`，Dart 侧 `SystemStats.fromJson` 镜像解析，只追加不改名）；首页顶部的"识别服务"统计条是**后端进程树**口径，两者并存。无 NVIDIA 显卡时显存/GPU 行显示"不可用"（识别引擎本就依赖 CUDA）；数据需后端运行中。

## AI 辅助（本地 Ollama / 外部模型 API）

编辑器的 AI 辅助功能——单字辅助识别、标点辅助识别、整行裁决（全本/本页/本行识别时）、识别框诊断——默认走本地 Ollama 服务；也可在「AI 辅助设置」顶部切换到**外部模型 API**（OpenAI Chat Completions 兼容协议）。

- **本地 Ollama**：适合有显卡、数据不出本机的场景；设置页按本机硬件推荐模型并一键拉取。
- **外部模型 API（多供应商）**：适合没有本地显卡或想要更强视觉模型的场景。可同时配置多家供应商（内置智谱 GLM / DeepSeek / Kimi / 通义千问 / SiliconFlow / OpenAI 常用预设，选预设自动填地址，也支持自定义 OpenAI 兼容网关），每家各自填地址与密钥、维护自己的模型列表（「测试连接并获取模型」拉取勾选或手动添加）；「模型选择」里为视觉/文本槽位各选「某家供应商的某个模型」——视觉用智谱、标点用 DeepSeek 这类混搭开箱即用。
- 两种来源各保留一份完整配置（地址、密钥、视觉/文本模型），随时切换互不覆盖。密钥只保存在本机；注意视觉类辅助会把裁出的字图/行图上传给所选外部服务商。
- 「AI 模型对比」页支持两种来源**混选同场对比**：本地与外部模型同时勾选（各带「本地/外部」来源标签，外部条目附供应商名），在真实书页上并排对比它们在四项辅助任务上的输出与耗时；排名、程序判断徽章按「来源+供应商+模型」分别聚合。
- **AI 并行度**（设置页「AI 并行度」卡片）：控制整行裁决同时发出的行请求数（整本识别与按主区拆分两条链路共用），四档可切——**智能**（压测过直接用实测值、没测过按显存估算，且永远给编辑器手动操作保留 1 条快速通道）/ **最大效能**（按压测实测上限跑满）/ **低显存**（恒 2 条）/ **手动**（步进选择，可填上限＝压测实测值，未压测按显存保守）。面板常驻**「测试并行数」**按钮（四种模式都能测）：自动从 1 条逐档爬坡直到测出真实上限（不看任何手填值）——先发 1 条预热（模型加载不计档），每档并发发**真实形态的行裁决请求**（合成行图+单字图、与 analyzeLine 逐字同款的 prompt、输出上限 256）——极小无图请求测不出视觉编码与显存的真实占用；任一档失败/超时，或并发档最长耗时超过单条基准 3 倍 + 15 秒（识破服务端排队串行，"排队轮完"不算过）即停，显存占用达 95% 或超 10 分钟自动中止、可随时取消、绝对上限 32；实测值供智能/最大效能直接采用，并即时放宽/收紧手动可填上限。压测结果缓存 30 天（换模型作废；缓存 v2 起为真实形态口径）。压测对象：本地 Ollama，以及**外部模型 API 填了本机环回地址**的情形（`http://127.0.0.1:9094/v1` 这类——one-api/LiteLLM/llama.cpp server 等本地 OpenAI 兼容网关，显存看门狗照常生效）；云端地址不适用（并发由服务商限速控制），局域网地址也不放开（那是另一台机器，本机显存看门狗无意义）。
- **识别进程数**（设置页「识别进程数」卡片，AI 并行度之后）：Kraken 整行识别引擎的 daemon **进程池**大小——首页状态条的"**识别进程 x/y 路**"显示的就是它（就绪/计划），与 AI 并行度是两套独立机制（后者管 AI 裁决请求并发，本项管 OCR 进程数）。**自动**＝后端按显存预算（单进程空载实测×负载系数）、CPU 物理核与内存自动决策（决策理由进后端日志）；**手动** 1..12＝经 `OCR_KRAKEN_WORKERS` 环境变量覆盖（后端启动时生效）。「应用并重建进程池」立即按当前设置重建（识别进行中拒绝；重建=排空旧池+逐个加载模型，约半分钟到几分钟）。「测试进程数」压测与 AI 压测同引擎同判据（最长耗时 ≤ 单条基准×3+15s、显存 95% 看门狗、15 分钟预算）：每档先把池重建到 k 个再同时发 k 路单行识别探针，测完池恢复原设置，实测值可一键设为手动并立即重建；结果缓存 30 天。

## 单字识别视图的重识别口径

编辑器详细（单字识别）视图里，涉及字框的识别入口分三类，AI 辅助一律按「AI 辅助设置」的开关决定是否参与（开启时识别后追加 AI 整行三步裁决）：

- **「重新识别本行单字」**（行标题刷新图标）：**严格保留本行现有字框**（含手工调整/新画的框），只对每个框重新 OCR 填字——即使整行读法与字框数对不上也不弃用人工框重切（旧版会把数量不一致的人工框整批换成自动切分框）。手工调过的行框几何同样不被后端外扩覆盖。
- **「重新切割本列」**（剪刀图标）：推倒重切——丢弃现有字框，整列重新拆字 + 识别（行框外扩到整列墨迹，含并排双列拆分）。
- **字框几何变更**：新画字框、以及**调整尺寸/移动位置**都会在松手后自动对该框重新识别（与新画框同体验；识别期间用户手动改过文字则不覆盖）。「行内重切」页的「识别填字（保留当前框）」与「重新识别本行」同口径严格保留框几何。

## 墨迹归类（单页版 / 全书版）

编辑器工具栏的「墨迹归类」按钮（hub 图标）把正文字块按**墨迹形态**（笔画形状，与识别文字无关）聚类分组——同一字形的实例聚在一起，可整组统一改字或点缩略图单独改字。

- **单页版**：本页字块聚类。组内文字支持**点选**（单击选中/取消）与**框选**（按住拖出橡皮筋批量选中，起点在已选中格子上则为减选；组头部有**选择全组 / 反选 / 取消选择**三个按钮）——「确认所选」只把选中的非空文字置为已确认并立即保存，效果与「确认并保存」相同（文字转绿色确认态；某页所有字都确认过时整页转绿框、计入训练数据）。空文字不参与确认，需先补字。**已确认的字默认从组里隐藏**，工具栏「显示已确认」开关可回显（绿色态），组头部的绿色 ✓N 徽标提示被隐藏的数量。
- **全书版**（单页版右上角书本图标，或编辑器「更多操作 → 墨迹归类（全书版）」）：指定**页数范围**（或整本书）跨页聚类——同一字形在全书各页的实例聚成一组（如「之」在全书的 200 个实例），选中后整组改一次字全书生效。交互与确认口径与单页版一致（点选/框选 → 确认所选，已确认默认隐藏 + 显示开关），逐组确认即逐页落盘。字格页号旁有**定位按钮**（或单字修改对话框点「定位到所在页」）：回到编辑器直接跳到该字所在页并选中闪烁该字，方便结合上下文核对。**双击字格**（或在单字修改对话框点「行内重切」）可打开该字所在行的**行内重切**页：按行的排版方向以竖排/横排卡片展示行图与单字识别区，可拖角调整/拖动/新画/删除字框，或「重新切分」「识别填字」走识别链路；几何被改动过的字自动重置为待确认（此前确认过的字因选取变化需重新确认），应用后「重新归类」即可把新字块聚回分组。大组默认折叠显示前 60 字，可展开全部；字图按需从后端裁取缩略图，大书不占内存。未归组单字（全书只出现一次的字形）默认折叠。大书聚类耗时可达分钟级，可先小范围试跑；**聚类结果按书缓存**（页范围+阈值+字块几何摘要一致即直接复用，改字/确认/标记不触发重算，调整字框或换图才重算），二次打开秒进。
- **特殊字标记（两个版本通用）**：归类时遇到**可能裁分有问题**或**暂时无法识别**的字，点选/框选后点组底部的「标记（N）」按钮打特殊字标记（选中的字已全部标记时该按钮变为「取消标记」」；单字修改对话框里也有「标记为特殊字」开关，可顺手打/撤。标记随页标注落盘（`marked` 字段），带小旗角标的字在编辑器详细视图的字 chip 上也有深橙点提示；编辑器里可从三处打/撤标：字属性面板开关、轻点字 chip 弹出的快捷候选条底部「标记特殊字」按钮（与文字一起关闭浮层时统一提交）、墨迹归类页的「标记」按钮。工具栏「**隐藏标记**」筛选把已标记的字隐去不干扰正常归类；「**只看标记**」（与隐藏标记互斥）只显示标记字——**全书识别完成后切到全书版开「只看标记」，即可把整本书存疑的字集中筛出来逐组校对**（改字/确认/行内重切都可用，校对完成用「取消标记」清掉）。标记独立于确认状态：打标不改变文字与确认口径，统计行显示当前范围内的特殊字总数。

## 模型训练与反哺识别

编辑器工具栏的「模型训练」图标（ school ）进入训练页，可训练 5 类模型：

| 模型 | 任务 | 反哺方式 |
|---|---|---|
| 单字检测 | YOLO 检测 | 启用后整页识别优先用它切字（替代投影切字） |
| 单字候选分类 | 分类 | 候选字（“这个字可能是什么”）优先由你校正过的字文本训练的分类器给出 |
| 行检测 | YOLO 检测 | 行框由模型输出，字框按中心归行 |
| 自然段检测 | YOLO 检测 | 整页识别直接返回模型分段（替代规则分段） |
| 正文区检测 | YOLO 检测（多类） | 整页识别直接返回模型版面区（带类别） |

**版面区多类**（`main_text` 正文 / `header` 页眉 / `footer` 页脚 / `page_number` 页码 / `margin_note` 眉批；类别词表在 Dart/Python 两侧同序，`main_text` 恒为类别 0、新类只追加）：编辑器主区视图可给区域选类别（按类别配色），标题栏下方工具栏提供「新框类别」快切芯片与**快捷键 1~5**，高频页面操作（旋转/镜像）也横排在同一工具栏直达；「只识别正文」只把 main_text 与 margin_note 当正文边界——页眉/页脚/页码里的行被过滤，眉批行保留并按夹注打标。主区视图提供「预标注版面区」（规则 + 跨页一致性建议）与「AI 整页预标注」（视觉模型判定 + 后端墨迹几何精修；需在 AI 辅助设置开启），预标注结果均为待确认候选、不覆盖已有区域；主区快设页可全书批量「自动加页眉/页脚候选框」（原「规则预标注」，开跑前可选仅未确认页或全部页面），也可「按参考页适配」——选一页画好的页做参考，把它的正文/页眉/页脚/页码等类别框（可勾选）按两页尺寸比例线性映射复制到其他页（只写框不识别、**不自动确认**，结果为待确认候选；页眉/页脚/页码逐页墨迹判空——该页这个位置没有内容的框不落，检测失败保守保留；范围可选仅未确认页/全部页/指定页范围；参考页本身、校对完成的页与「确认无正文」的页恒跳过）；配套「取消确认」可按页范围把已确认页整段退回未确认（只清确认标记，框保留）。识别返回还会带"正文区与页眉/页脚/页码区重叠"的冲突提示（只标记不裁决）。

流程：**在编辑器中校正 → 训练页「生成数据集」→「开始训练」 → 完成后「启用」 → 重新识别即走自训模型**（生成与训练是两个独立按钮）。**增量导出**：只写新增/内容有变化的页（digest 判定，同页覆盖重写）；打开训练页自动检查并后台导出新增（按钮上也显示"X 页待导"）；旁附强制重导入口（按当前书库标注重写全部已导出页）。

**统一数据集目录与跨机迁移**：数据集根目录可在模型管理页配置（默认 `python_service/datasets/`）。目录下的 `manifest.json` 是导出清单（每书每层已导出的页、样本数、每类分布）——**把整个数据集文件夹拷到另一台电脑，统计与记录随行**；统计口径 = 已导出数据，**删除书籍任务不影响清单、样本文件与统计**（书库清空也能看数字）。**确认即自动导出**：任何确认类保存（编辑器两种确认、主区快设「确认并下一页」、墨迹归类组确认等一切经存储层咽喉点的写盘）触发防抖增量导出（与训练页打开时的自动导出共用 `/train/export`，后端加导出互斥锁防并发记账丢失）。**region_det 全量导出**：凡有已确认版面区（box_confirmed，主区/页眉/页脚/页码/眉批/图片/表格任意类别——主区快设、编辑器、预标注后人工确认都算）的页全部进入版面区训练集，与整本识别是否完成解耦；其他四层照常按页增量。**撤销也回账**：确认被撤销（主区快设「取消确认」按页范围整段退回、编辑器单字校对视图「全书改回未保存」——后者把「确认并保存」的绿框页全部退回未确认，识别框与文字保留）后，这些页不再产出任何样本；两个入口都会在操作后自动触发一次增量导出，后端随之**删除这些页已导出的样本文件并回退 manifest 统计**（manifest 里已登记、但标注不再产出样本的页在每次导出时清理；书里已删除的页与书库外的书仍保留旧数据）。**页眉页脚只作版面标注**：已确认排除类区（页眉/页脚/页码/图片/表格）内的行/字/段落框不进入 line_det/char_det/paragraph_det/char_cls 训练数据与本书计数（框中心点落在区内即排除，proposed 候选不挡数据；Dart 侧 `PageAnnotation.centerInConfirmedExcluded` 与 Python 侧 `train_datasets.confirmed_excluded_regions` 是同一协议的两半），页眉/页脚本身作为 region_det 的类别样本照常收录。样本文件名带书籍 ID 前缀、train/val 按页稳定划分（同一页永远落同一集合）。旧版按书存放的数据集（`datasets/<项目ID>/`）首次访问时自动迁移进全局目录；旧 `_meta.json` 存量首次自动转为清单基线。Kraken 确认行数据同样按全部书籍汇总（`kraken_training/datasets/_global/`）。**样本图片入库时自动处理**：长边超过 2560 的素材先降采样再统一存 JPG（q95；标注为归一化坐标，缩放不影响标签），已合规的 JPG 原文件直接复用不二次压缩；重写某页时清理旧扩展名文件防同页双样本，存量 PNG 样本不强制迁移、照常参与训练。

**训练模型目录与模型管理**：训练产物目录可配置（默认 `models/trained/`，模型管理页「数据与模型位置」）；「启用」= 把选定的 .pt（run 的 best.pt 或任意一轮检查点）拷贝到应用模型目录（`models/active_<层>.pt`）。模型管理页可按 run 启用/停用/删除（删除前若该 run 正被使用会先自动停用；确认框显示磁盘占用），每个 run 行有「训练曲线 · 按轮启用」入口——曲线弹窗里按逐轮指标挑 best/last/第 N 轮检查点直接启用；层卡「全局」行显示当前启用来源（run 目录 · best/第 N 轮，来自注册表 `active_source`）；并提供数据集/训练模型/应用模型三个文件夹的直达打开。

**发版打包（.zjpack）**：模型管理页「打包发版」按钮（或 CLI `python tool_pack_models.py`）把**当前各层启用中**的模型（无启用层打基线；弃用的实验 run 永不进包）与 Kraken 识别模型打成单个 Ed25519 签名的 `models_release.zjpack`，随安装包分发——打包是纯手动动作，训练闭环不经过它。用户机上散装模型文件不再随安装包分发，识别链路回落顺序：环境变量覆写 > 注册表启用/散文件 > 发行包（验签后按需物化到 `.model_cache/`，包损坏只记日志并按无包降级，不影响识别）。签名私钥在 `release_keys/`（只留管理员机，安装包已排除），公钥内嵌 `model_store.py`；格式基准见 `python_service/zjpack.py`。

**训练曲线与中间存档**：每层卡片可设「中间存档」（每 N 轮保存一个检查点，默认每 10 轮）；「训练曲线」弹窗画出逐轮指标/损失折线（训练中实时刷新、可切历史训练），并自动给出过拟合/收敛提示——若指标峰值出现在中段后回落，可直接把峰值附近那一轮的检查点「启用」为当前模型，不必等全部轮数跑完。

注意：训练占用 GPU（期间识别会变慢）；关闭应用会中断训练；首次训练需联网下载基础权重（yolov8s.pt / yolov8n-cls.pt）。同一本书积累 30~50 页校正后再训练效果较好；未启用任何自训模型时识别行为与原来完全一致。

### 对比测试（模型训练页的「对比测试」标签）

同一页图片识别两次并排/滑动叠加比对。对比对象可选：**与基线**（不使用任何自训模型的原始管线）或**与另一模型**（同层两次训练 run / 检查点互比，直接看两次训练的真实识别差异）。模型A/B 除选哪次训练（run）外，还各有「轮数」下拉——从 `/train/curve` 的检查点清单里选 best / last / 第 N 轮（项内带该轮主指标；中间轮检查点数百 MB、加载较慢），选中哪一轮就测哪一轮，也可两侧选同一 run 的不同轮互比。支持五个检测层（正文区/段落/行/单字/单字候选分类）的单层替换对比——只有被测层套用所选模型，其余层照常；**画布只画被测层的框**（测正文区检测就只画正文区框，不被行/字框淹没），面板计数行仍显示全部层级数量；单字候选分类模式以本页人工确认文字为标准答案统计两侧候选命中率（Top1/3/5/10、平均排名、逐字明细）；识别消融模式在书库人工确认行组成的冻结评测集上跑 A/B/C 三档，量出识别准确率里模型与链路代码各自的贡献。底部日志面板实时显示识别过程关键行，可确认模型确实被加载使用。

### 训练准备进度

训练页同时展示「数据准备」和「训练运行」进度。数据准备只累计已人工确认的标注，切换 n / s / m 模型后即时更新目标和还需确认的数量。单字分类也可选择对应的 `-cls` 模型，并同时检查样本数和字类数。

| 模型 | n 目标 | s 目标 | m 目标 |
|---|---:|---:|---:|
| 正文区检测 | 30 | 90 | 180 |
| 自然段检测 | 60 | 180 | 360 |
| 行检测 | 120 | 360 | 720 |
| 单字检测 | 300 | 900 | 1800 |
| 单字分类 | 500 样本 / 50 字类 | 1500 样本 / 120 字类 | 3000 样本 / 240 字类 |

这些数值是软件首版的准备门槛，集中定义于 `python_service/train_data.py` 的 `TRAINING_REQUIREMENTS`，不是识别准确率保证。未达到所选模型门槛时，界面和本地训练接口都会提示缺口；达到门槛后仍需检查训练/验证集是否有效，并人工评估训练结果。数据准备进度按**全部书籍累计**统计（数据集全局共享）。

## 表格与插图标记（+84）

古籍里的年表、职官表等**有线表格**和版画插图此前会被当成正文误切字。现在版面区词表新增**图片（figure）**与**表格（table）**两类（快捷键 6/7 快切，画框标记与其他版面区同一套交互）：

- **门控排除**：标记后整个区域在字检测前被抹成页面底色（与页眉/页脚同一门控路径），格线与插图墨迹不再产出误切字；图/表与正文区的重叠属正常版面，不参与冲突提示。
- **表格识别**：选中 table 类主区 → 面板「识别表格」→ 后端形态学提取格线还原网格（行/列/合并单元格，断线自动桥接），每格按**格内文字方向自动判定**（瘦高格竖排、扁格横排、方形格随页面）逐字识别（Kraken 同源读法）。横版/竖版书页同一路径；页面斜的先批量摆正再识别。
- **表格校对页**：按真实网格布局逐格校对（合并格真跨行列），竖排版面默认按阅读序列从右往左摆（表头在右），每格显示原图缩略与格线示意；支持单格确认/全部确认、重新识别、导出 Markdown/TSV（剪贴板 + 存文件）。结果随页标注落盘，页面旋转/跨页拆分时几何与行列自动同步。
- **自动预标注**：规则预标注（现更名「自动加页眉/页脚候选框」等入口）横竖两路并行走：横排页按顶/底墨迹条带，竖排页按列投影 × 行簇切分（书耳题名/天头眉批列/边栏书名/版心题名叶码逐列出框，不再并成横向大框），页缘装订阴影/纸边碎屑/版框残线由页缘清零、尺寸、填充率与横贯暗带四道门挡掉。预标注还会扫描整页格线网格结构，把候选表格区以 proposed 状态插入供人工确认/拒绝；残余误报直接拒绝即可。主区快设的全书批量入口开跑前可选范围：**仅未确认的页面**（默认，跳过带"已确认"角标的页）或全部页面，选择会记住。
- 无线表格暂不支持：识别失败会明确提示「未检测到表格格线」。
- 人工确认的 figure/table 框会进入 region_det 训练集，积累够了可在训练页训出自动检测（与正文/页眉等五类同一反哺链路）。

## 识字数据包（两种模式）

**正文识字数据包（含字图/候选）**——已确认快照：勾选后只导出已确认（confirmed）的
`main_text` 字块，并为每个字生成图片和最多 10 个 OCR 候选（含分数）。没有标注的页面会在导出时自动执行正文分区、分行和切字。用途是训练快照与阅读导出，不上传命迹。

```text
crowd_dataset/
├── manifest.json       # 书籍元数据、版式设置、页面哈希和生成器信息
├── blocks.json         # 页面→行→字、坐标、稳定 char_uid、候选文字
├── pages/              # 原始页面副本
├── lines/              # 正文行图片
├── chars/              # 单字图片
├── logs/export.log
```

**识字任务包（未确认字，供命迹众包）**——勾选后导出 `crowd_tasks/`（旁边生成
`crowd_tasks.zip`）：为「未确认且未拒绝」的 `main_text` 字块生成字图与候选，
候选 A+B 双轨——char_cls / 识别分歧保存的备选优先，不足 10 个时以机器当前
读法兜底补位（排末位），保证每题至少一个可选字符；行结构仍保留全部正文字
（含已确认字，`for_task: false`，不出图）以便整书文本重建；页面只要求划定过
正文主区（几何尚待校对也可以先众包）。任务包不需要整页图与行图，体积小、
导出快。勾选识字类导出时可填写**页码范围**（起始页/结束页，1 基、含首尾），
只导出指定页，便于小规模测试与分批分发。

上传命迹管理后台后只有 `for_task: true` 的字会成为识字任务；后台确认终字后导出
「共识快照 JSON」，在本项目首页「导入命迹识字共识」按 `char_uid` 写回——写回的
文字标记为 `needs_review`（待复核），在编辑器中人工复核并「确认并保存」后才成为
训练数据；导出之后才人工确认过的字不会被共识覆盖。

导出目录旁边还会生成可选归档包（`.zip`）。

项目创建时可以设置横排/竖排、横排左右方向和竖排上下方向，并填写作者、版本、卷册、来源等可选书籍元数据。旧版 `project.json` 缺少这些字段时会自动使用竖排和项目名作为书名。

## 跨页拆分（左右页合扫的书）

有的书 PDF 每一页是左右两个书页合扫的跨页图。编辑器「更多操作」菜单的「跨页拆分（左右页拆开）」把整书拆成单页：

1. **设页序**：选「先左后右」（现代图书）或「先右后左」（古籍竖排从右往左读），决定每张跨页拆出的两页谁在前。
2. **定中缝**：软件把窗口内所有页半透明叠加成一张图，扫描偏移与贯穿全书的黑色中缝竖带一眼可见；拖动橙色中缝线（点击跳线、±1/±10px 微调）对准中缝。
3. **拆分**：点「拆分并应用」，逐张按中缝比例切图，N 张跨页变成 2N 页，已识别页的标注按中缝拆分保留，无标注页自动排队整本识别。

拆分可逆：拆分前的原始页面与其标注原样保留在盘上，回到拆分页可「恢复拆分前」，或调整中缝后「重拆」（重新基于原始页面，会覆盖拆分页此后的修改）。建议在导入后、校对前完成拆分。

## 标注与训练规则

- **区域门控（正文独享下游识别）**：训练与标注层面正文、页眉、页脚、页码、眉批、图片、表格七类版面区都要标注，识别模型（Kraken 行识别）学习所有人工确认过的行——包括页眉页脚里的行。但整页识别管线里只有正文区域会继续做段落划分、行划分、单字划分与文字识别：region_det 先行检测整页版面区，页眉/页脚/页码/图片/表格区在字检测之前就被抹成页面底色（临时门控图），这些区域不再产出任何行/字/段落，后续 Kraken 识别自然读不到；区域框本身仍随识别结果输出，供编辑器标注与确认。**人工已确认区优先于模型预检**：重识别（/segment、/segment_lines_in_region 的 `gate_regions`）随请求带入本页已确认版面区时直接用作门控与结果的 main_regions（不跑第二遍 region_det，确认身份不因重识别丢失）——region_det 模型还没训出来时，主区快设确认过的页眉/页脚同样生效。眉批（margin_note）按"标记不删除"哲学保留在管线内，行照常识别并打夹注标；表格/插图的重叠冲突审计不参与（图/表在正文区内是正常版面）。region_det 模型不可用、当页没有排除类区、也没有已确认区可带入时退回整页识别（无安全边界不强切）。
- 保存分两种：「临时保存」只落盘修改、不确认（翻页/退出自动触发），「确认并保存」才把整页标注固化为训练数据。
- 所有训练数据出口都只认已确认数据：训练页的数据集生成、正文识字数据包、导出页的 YOLO 数据集（整页门槛，未确认页跳过）与 CRNN 行序列（逐行过滤）。「阅读顺序 JSON」是版面信息，仍全量导出。
- 编辑器「更多操作」（⋮）菜单提供「本书重置为未确认」：把全书标注状态一次性回到 proposed（识别框几何、文字、候选全部保留），用于清理被旧版"翻页自动确认"误标为已确认的数据，重置后需重新逐页确认。
- 标注状态统一为 `proposed`、`confirmed`、`rejected`、`needs_review`；Python 后端用 `metadata.normalize_status` 把历史词（`reviewed`/`accepted`/`approved` 等）归一到四态。Flutter 侧另有页级 `reviewed` 布尔字段（整页「已看过」标志，仍在正常读写），与四态契约并存、语义不同，不是兼容遗留。
- 正文识字数据包只导出已确认的正文单字，并保留 `legacy_id`、`char_uid`、像素坐标、归一化坐标、候选字、OCR 修订号和模型版本。识字数据包内的 `char_uid` 以 Flutter 导出器（`crowd_dataset_exporter.dart`）生成的格式为准（sha256 前 24 位十六进制、无前缀）；识别结果 JSON 里 Python 端 `metadata.stable_uid` 生成的 uid（带 `char_` 等前缀）是另一套身份体系，只用于标注身份，两套不互换。
- YOLO 的正文区、自然段、行、单字检测数据集，以及 `char_cls` 单字分类数据集均按页面划分 train/val，避免同一页面泄漏到两个集合。
- 训练结束后模型只登记到注册表，不会自动替换当前模型；在训练页查看指标和样例后手动启用，随时可以停用回退。
- 用户识字任务的在线提交暂不在本项目中处理；Mingji 众包流程为：导出「识字任务包（未确认字）」上传命迹管理后台 → App 用户答题 → 后台按答案分布确认终字 → 导出「共识快照 JSON」→ 在本项目首页「导入命迹识字共识」写回标注（按 char_uid 匹配，写回文字标记为待复核，由编辑器人工复核确认）。
